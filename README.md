# 🛡️ سامانه مدیریت فعالیت‌های امنیتی

نرم‌افزار تحت وب برای **ثبت، مدیریت و گزارش‌گیری** فعالیت‌های تیم امنیت — جایگزین فایل‌های Excel پراکنده با یک سیستم متمرکز، ساده و قابل توسعه.

هر اطلاعات در سامانه به‌صورت **Activity (فعالیت)** ذخیره می‌شود و هر Activity متعلق به یکی از حوزه‌های امنیتی است.

---

## 🧩 معماری فرانت‌اند — Vue 3 (SFC + Vite)

تمام رابط کاربری تعاملی با **Vue 3 نسخهٔ 3.5.13** و به شکل استاندارد **کامپوننت‌های تک‌فایلی (`.vue` / SFC)** ساخته شده است:

- **سورس‌ها** (`frontend/src/`): هر صفحه یک پوشه با فایل‌های `.vue` واقعی — ورود، داشبورد (KPIها، چیپ‌های بازه، جدول‌ها)، فعالیت‌ها، فرم فعالیت، جزئیات فعالیت، کاربران، فرم کاربر، حوزه‌ها، فیلدها، گزارش‌ها (جدول + انتخابگر ستون‌ها + منوی خروجی)، ورود Excel، تنظیمات، تسک‌ها و گزارش چاپی؛ به‌علاوه کامپوننت‌های مشترک پوسته (هدر، توست، مودال تأیید، تقویم شمسی، نوار پیشرفت) و نمودارها (`components/charts/`) و کتابخانه‌های `lib/` (ابزار، تاریخ جلالی، سازنده‌های SVG)
- **بیلد** (`frontend/` → `static/dist/`): با `npm run build` (Vite 6) برای هر صفحه یک باندل ماژولار (`<script type="module">`) تولید می‌شود و باندل‌های خروجی همراه پروژه کامیت شده‌اند — **برای اجرا نیازی به Node.js نیست**
- **اجرای سامانه همچنان فقط** `python app.py` **است**؛ Flask همان HTML را سرو می‌کند و هر قالب فقط باندل بیلدشدهٔ خودش را لود می‌کند. همه‌چیز آفلاین است (Vue به‌صورت داخلی باندل شده، فونت Vazirmatn محلی — بدون هیچ CDN)

### توسعه فرانت‌اند (فقط در محیط توسعه)

```bash
cd frontend
npm install
npm run build     # خروجی به ../static/dist می‌رود و قالب‌ها همان را لود می‌کنند
```

## 🚀 اجرا (خیلی ساده)

```bash
cd secman
pip install -r requirements.txt
python app.py
```

سپس مرورگر را باز کنید: `http://127.0.0.1:5000`

| نقش | نام کاربری | رمز عبور |
|---|---|---|
| مدیر | `admin` | `admin123` |

## ✨ امکانات

### 🏠 داشبورد (فقط آمار)
نمودار فعالیت‌ها • نمودار حوزه‌ها • نمودار وضعیت • روند ماهانه • آخرین Upload های Excel • آخرین فعالیت‌ها (۵ مورد)

### 📝 فعالیت‌ها (مهم‌ترین بخش)
مشاهده، ثبت، ویرایش، حذف • جستجو و فیلتر پیشرفته • خروجی Excel و PDF • انتخاب حوزه و **نمایش فرم مخصوص همان حوزه** (کاملاً پویا و از پایگاه داده) • **تقویم شمسی پاپ‌آپ** برای همه فیلدهای تاریخ • بخش‌های مشترک **«مشخصات درخواست‌دهنده فعالیت»** و **«مشخصات تحویل فعالیت»** (اختیاری) در همه فرم‌ها • **تخصیص تسک به کارشناس** توسط مدیر هنگام ثبت فعالیت

### 📥 ورود از Excel
انتخاب حوزه → انتخاب فایل → ثبت. هر ردیف = یک Activity. پیام نتیجه: «۲۸ فعالیت با موفقیت ثبت شد.» یا جزئیات ردیف‌های خطادار. **قالب نمونه هر حوزه** به‌صورت خودکار تولید و قابل دانلود است.

### 📊 گزارش‌ها
فیلتر: حوزه، کارشناس، شماره تیکت، بازه زمانی، ضمیمه — خروجی: **Excel، PDF، CSV**
خروجی PDF شامل **داشبورد تصویری** (سهم حوزه‌ها، نمودار وضعیت، روند ماهانه) بر اساس **همان فیلترهایی** (از جمله بازه زمانی) که تعیین کرده‌اید.

### 👥 کاربران (فقط دو نقش)
| مدیر | کارشناس |
|---|---|
| دسترسی کامل: فعالیت‌ها، کاربران، حوزه‌ها و فیلدها، ورود Excel، گزارش، تنظیمات | فقط فعالیت‌های خودش: ثبت/مشاهده/ویرایش، ورود Excel، گزارش خودش |

### 📎 فایل‌های ضمیمه
각 Activity می‌تواند چند فایل داشته باشد (PDF، Word، Excel، JPG، PNG، ZIP — قابل تنظیم).

### 🗓️ تقویم شمسی
همه تاریخ‌ها **شمسی** نمایش و وارد می‌شوند؛ در پایگاه داده **میلادی** ذخیره می‌شوند تا مرتب‌سازی و جستجو دقیق بماند.

### 🛠 بدون کد هاردکد
فرم‌ها، فیلدها و حوزه‌ها همگی در پایگاه داده‌اند. در صفحه «ثبت فعالیت» دکمه **«مدیریت فیلدهای این حوزه»** (فقط مدیر) امکان افزودن/حذف/ویرایش فیلدها را بدون مراجعه به تنظیمات فراهم می‌کند.

---

### 🎨 رابط کاربری
طراحی حرفه‌ای با آیکن‌های SVG اختصاصی (بدون ایموجی)، فونت **Vazirmatn** (به‌صورت داخلی در پروژه — بدون نیاز به اینترنت)، سایدبار تیره با وضعیت فعال گرادیانی، کارت‌های آماری، جدول‌های داده تمیز، تقویم شمسی پاپ‌آپ و نمودارهای SVG دست‌ساز با گرادیان و ابزارتیپ. استایل‌ها در `static/css/` و سورس‌های فرانت‌اند در `frontend/src/` (باندل‌های بیلدشده در `static/dist/`) نگهداری می‌شوند.

### 🗂️ حوزه‌های پیش‌فرض (۱۳ حوزه)
استخراج IP آسیب پذیر (با زیرحوزه‌های دیتاسنتر / حاکمیتی غیرزیرساختی / پایه)، رصد، ارزیابی امنیتی وب (با پروفایل‌های ۰ تا ۶)، اخبار پورتال ماهر، ارزیابی امنیتی اندروید، بدافزار، ابزار، دوره آموزشی، مستندات فنی، پایش و غربالگری، خدمات مشاوره‌ای، خدمات موردی، شیفت آنکال — فیلدهای هر حوزه دقیقاً مطابق فرم واقعی تیم است و از «مدیریت فیلدها» قابل تغییرند.

## 🗄️ ساختار پایگاه داده

| جدول | کاربرد |
|---|---|
| `users` | کاربران |
| `domains` | حوزه‌ها (۱۳ حوزه پیش‌فرض) |
| `activities` | فعالیت‌ها |
| `form_fields` | فیلدهای هر حوزه (پویا) |
| `activity_values` | مقادیر هر فیلد |
| `attachments` | فایل‌های ضمیمه |
| `excel_imports` | لاگ ورودهای Excel |
| `settings` | تنظیمات سامانه |

```
├── requirements.txt
├── templates/        # قالب‌های HTML رابط کاربری (RTL، فارسی)
├── static/
│   ├── css/          # app.css (تم اصلی) + print.css (گزارش چاپی)
│   ├── js/           # app.js (تقویم شمسی) + charts.js (نمودار SVG)
│   └── fonts/        # فونت Vazirmatn (woff2)
├── uploads/          # فایل‌های ضمیمه + لوگو (هنگام اجرا ساخته می‌شود)
└── secman.db         # پایگاه داده SQLite (از اولین اجرا ساخته می‌شود)
```
